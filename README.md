## 1. 프로젝트 목적
> 흩어져 있는 전국의 팝업스토어 정보를 한곳에서 편리하게 탐색하고 실시간 예약까지 가능한 통합 웹 서비스

## 2. 프로젝트 내용
기존 소수 웹페이지의 한계로 인한 **'팝업 인지 및 예약 효율 저하'** 문제를 발견하고, 이를 보완하기 위해 다음과 같은 핵심 가치를 중심으로 기획되었습니다.

* **편의성** : 복잡한 정보를 통합하여 한 곳에서 효율적으로 해결 가능
* **사용자 중심** : 맞춤형 정보를 제공하여 사용자에게 최적화된 경험 선사
* **실시간 예약** : 예약 관련 기능과 정보를 실시간으로 처리 및 확인 가능
* **정보 소통 활성화** : 게시판 및 후기 기능을 통해 사용자 간 활발한 정보 공유

## 5. 프로젝트 결과 및 회고
### 프로젝트 성과 (완성도 약 70%)
1. **통합 플랫폼 구축**: 전국 분산되어 있던 팝업 정보를 한눈에 보고 예약하는 비즈니스 모델을 실제 기능으로 구체화했습니다.
2. **기술적 스택 확장**: 외부 오픈 API(카카오맵), 이미지 파일 처리, 데이터베이스 정규화 및 관계 설계를 직접 수행하며 풀스택 역량을 강화했습니다.
3. **사용자 친화적 서비스 경험**: 소셜 로그인부터 실시간 예약 상태 변화에 따른 유기적인 기능 연동까지, 엔드 투 엔드(End-to-End) 흐름을 고려한 UI/UX를 고민했습니다.

### 한계점 및 개선 방향
* **데이터 수집 한계**: 초기 적재된 정적 데이터만 노출되는 한계가 있어, 향후 **웹 크롤링 및 외부 스케줄러 API 연동**을 통해 정보를 자동으로 수집·갱신하는 파이프라인이 필요합니다.
* **기능적 고도화**: 프로젝트 기간 제약으로 미처 완성하지 못한 리뷰 수정/삭제 및 마이페이지 내 상세 취소 프로세스를 보완하고, 나아가 **WebSocket 기반의 실시간 1:1 문의 채팅** 기능을 확장하고자 합니다.

### 프로젝트를 통해 배운 점
* **전체적인 시야 확보**: 프론트엔드와 백엔드를 동시에 아우르며 프론트단의 상태 관리(State)가 백엔드 DB 구조와 어떻게 유기적으로 연동되는지, **데이터의 전체 흐름**을 명확히 이해했습니다.
* **사용자 중심의 예외 처리**: 사용자의 입력 실수나 기기 환경에 따른 레이아웃 깨짐, 대량 마커 노출 시 가독성 저하 등의 문제를 직접 마주하며 **UI/UX 관점의 디테일한 예외 처리**가 서비스 완성도에 주는 영향을 크게 배웠습니다.
* **협업과 Git 브랜치 전략**: 팀원과의 원활한 협업을 위해 기능별 브랜치를 분리하고, 코드 병합(Merge) 과정에서 발생하는 충돌(Conflict)을 주도적으로 해결하며 **효과적인 형상 관리 프로세스**를 익혔습니다.
